ArgoCD Architecture: Root Application, Projects & Applications

This web application is live proof of GitOps in action. It is reconciled dynamically from Git using ArgoCD's App of Apps pattern. Below is the blueprint explaining how Root Applications, AppProjects, and Child Applications orchestrate your cluster.

💡
GitOps Single Source of Truth: Any manual change made with kubectl edit or kubectl delete on this service is automatically detected and reverted by ArgoCD's self-healing engine to match Git.

Pillar 1: The Root Application (App of Apps)

In standard Kubernetes, deploying 10 applications means managing 10 separate deployment commands. The App of Apps pattern solves this by using one "Root" ArgoCD Application whose only job is to create and track child Applications.

# root-application.yaml apiVersion: argoproj.io/v1alpha1 kind: Application metadata: name: root-application namespace: argocd spec: project: default source: repoURL: https://github.com/vmalani27/gitops-repo-apps.git targetRevision: main path: apps # Points to folder containing child Application CRDs destination: server: https://kubernetes.default.svc namespace: argocd syncPolicy: automated: prune: true selfHeal: true

🌟 Independent Lifecycles

Each component has its own card in the ArgoCD UI, enabling individual sync, rollbacks, and diff checking.

🚫 No Monolithic Failures

If one component has a syntax error, only that application turns OutOfSync; other services deploy normally.

Pillar 2: ArgoCD Projects (AppProject)

An AppProject provides logical grouping, governance, and RBAC boundaries. In enterprise setups, projects isolate team access and prevent applications from exceeding their security radius.

🔒 Source Repository Whitelisting

Restricts which Git repositories this project's applications can deploy code from.

🎯 Destination Whitelisting

Limits which Kubernetes clusters and namespaces workloads can be scheduled into.

🛡️ Resource Blacklisting

Prevents applications from creating privileged resources (e.g. ClusterRoles, CRDs, or Namespaces).

👥 Role-Based Access (RBAC)

Assigns read-only or sync privileges to specific developer groups and JWT tokens.

Pillar 3: The Child Application (This Demo App)

Defined in apps/demo-app.yaml, this Application manifest points to components/demo-app. It contains the instructions that deployed this exact web server.

# apps/demo-app.yaml apiVersion: argoproj.io/v1alpha1 kind: Application metadata: name: demo-app namespace: argocd spec: project: default source: repoURL: https://github.com/vmalani27/gitops-repo-apps.git targetRevision: main path: components/demo-app destination: server: https://kubernetes.default.svc namespace: demo-app syncPolicy: automated: prune: true # Deletes cluster resources when deleted from Git selfHeal: true # Overwrites manual cluster drift back to Git state syncOptions: - CreateNamespace=true
